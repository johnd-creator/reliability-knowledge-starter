3. Capture the actual HTTPS listener's PID, parent PID, `/proc` start ticks (PID reuse defense), service invocation and official generation. Private receipts are linked to the existing compatibility approval ID; each official generation has retained history. Status reports actual worker/runtime and the last approved generation. Missing/changed worker receipts produce UNVERIFIED, stale warning and readiness refusal even if systemd says zero restarts. No automatic reapproval after an internal restart.
4. Restore next-env only inside official startup/recovery, after verifying exact committed SHA, complete known byte transformation and the sole unstaged path. Staged changes, extra tracked/untracked changes, symlink, CRLF or any unknown content are refused. Preserve a private before/after hash, exact diff and original generated bytes before writing. No git reset, ignore rule or source exception. Ordinary preflight remains clean-only; it does not silently repair a running worktree.

The same-user developer is the trust boundary for private launcher files; these receipts do not introduce a new authentication scheme. Source/API compatibility equality checks, backup checks, HTTPS ownership and rollback remain mandatory.
